# Transitive license reports

This directory holds machine-readable license reports for every third-party
dependency Private Ballot pulls in, together with a short human summary of
what they contain.

Project-owned code is licensed `MIT OR Apache-2.0`. See the top-level
[LICENSE](../../../LICENSE), [LICENSE-MIT](../../../LICENSE-MIT),
[LICENSE-APACHE](../../../LICENSE-APACHE), and
[THIRD_PARTY_NOTICES.md](../../../THIRD_PARTY_NOTICES.md) for the project
license and canonical third-party attribution list.

## Reports

* `rust-workspace-licenses.csv` — every Cargo package the top-level workspace
  resolves (`Cargo.lock`). One row per package: name, version, SPDX license
  expression, upstream repository.
* `rust-src-tauri-licenses.csv` — every Cargo package the detached Tauri shell
  (`gui/src-tauri/Cargo.lock`) resolves. The shell has its own lockfile
  because it must remain hermetic from the workspace.
* `npm-production-licenses.json` — every npm package `gui/package-lock.json`
  installs in production mode (i.e. what actually ships in the built frontend).
* `npm-all-licenses.json` — every npm package `gui/package-lock.json` resolves,
  including devDependencies (the vite/tsc/tauri-cli build toolchain).

## How they were generated (2026-09-03)

Neither the machine nor the project committed `cargo-license` / `cargo-about`
during this pass. `cargo-license` reads exactly the same `license` and
`license_file` fields that `cargo metadata --format-version 1` already
surfaces, so the Rust reports were generated by walking that JSON directly:

```powershell
# Workspace
cargo +stable-x86_64-pc-windows-msvc metadata --format-version 1 |
  python -c "<the small extractor script kept in tools/, or inline>" `
  > docs\release\licenses\rust-workspace-licenses.csv

# Detached src-tauri
cd gui\src-tauri
cargo +stable-x86_64-pc-windows-msvc metadata --format-version 1 |
  python -c "..." > ..\..\docs\release\licenses\rust-src-tauri-licenses.csv
```

If you would rather use `cargo-license`, `cargo about generate`, or `cargo
deny check licenses`, install them and regenerate — the SPDX values will
match, and a `cargo deny` allow-list is a reasonable next step once the
project settles on one.

The npm reports were generated with
[`license-checker`](https://www.npmjs.com/package/license-checker):

```powershell
cd gui
npx --yes license-checker --json --production --relativeLicensePath `
  --out ..\docs\release\licenses\npm-production-licenses.json
npx --yes license-checker --json --relativeLicensePath `
  --out ..\docs\release\licenses\npm-all-licenses.json
```

Regenerate every report whenever `Cargo.lock`, `gui/src-tauri/Cargo.lock`, or
`gui/package-lock.json` changes.

## Result summary (2026-09-03)

**Rust workspace: 479 crates.** Every SPDX expression is a permissive
open-source license compatible with `MIT OR Apache-2.0` distribution.
Categories that warrant a call-out:

| Category | Count | Notes |
| --- | --- | --- |
| MIT / Apache-2.0 family (`MIT OR Apache-2.0`, `Apache-2.0 OR MIT`, `MIT/Apache-2.0`, `MIT`, `Apache-2.0`, `MIT-0`) | ~409 | The overwhelming majority. |
| BSD family (`BSD-2-Clause`, `BSD-3-Clause`, `0BSD`, `BSD-1-Clause`) | ~40 | Permissive; includes the Tari Triptych vendored crate and dalek. |
| ISC | ~4 | Permissive. |
| Zlib | ~7 | Permissive. |
| Unicode-3.0 | 18 | ICU / Unicode data. Permissive. |
| CC0 | ~4 | Public-domain dedication. |
| MPL-2.0 | 5 | File-level weak copyleft. All from the `webauthn-rs` family. Modifying an MPL-2.0 file would require publishing the modified file under MPL-2.0, but pure use / distribution alongside MIT-or-Apache code is fine. |
| BlueOak-1.0.0 | 2 | Permissive. `minicbor` / `minicbor-derive`. |
| WTFPL | 1 | Permissive. `newtype-ops`. |
| CDLA-Permissive-2.0 | 1 | Permissive. `webpki-root-certs`. |
| BSL-1.0 | 1 | Boost Software License, permissive. `xxhash-rust`. |
| Multi-license including LGPL as one option | 2 | `r-efi` is `MIT OR Apache-2.0 OR LGPL-2.1-or-later`. We take MIT/Apache-2.0; LGPL never applies. |

**Detached Tauri shell (`gui/src-tauri/Cargo.lock`): 727 crates.** Same
categories as the workspace, plus the extra ones Tauri and its Windows /
macOS platform crates pull in. No blocking license.

**npm production graph: 8 packages.** All permissive:

* MIT (4): `react`, `react-dom`, `scheduler`, `uqr`.
* `Apache-2.0 OR MIT`: `@tauri-apps/api`.
* `MIT OR Apache-2.0`: `@tauri-apps/plugin-dialog`.
* `OFL-1.1`: `@fontsource/poppins`.
* `UNLICENSED`: the private `tari-private-ballot` frontend package itself.
  `license-checker` treats a `"private": true` package with no SPDX field as
  "UNLICENSED"; the project-owned frontend now declares `"license": "(MIT OR
  Apache-2.0)"` in `gui/package.json`, but license-checker still labels the
  private root as UNLICENSED. This is cosmetic — the actual license grant
  for the frontend source is the top-level project license.

**npm full graph (with devDependencies): 29 packages.** Adds vite, tsc,
tauri-cli, and their small dependency graph. Only one new call-out:

* `lightningcss` (MPL-2.0). Vite build-time only; not shipped in the frontend
  bundle. File-level weak copyleft. Compatible.

**Conclusion:** the project is safe to publish under `MIT OR Apache-2.0`. No
GPL / AGPL / SSPL / BUSL / source-available / non-commercial dependency was
found in either graph. The MPL-2.0 entries are limited to unmodified use of
those crates; changing an MPL-2.0 file would require publishing that specific
file under MPL-2.0, but that has not been done anywhere in this project.

  version, static-link status, and MSI/NSIS notice text for the actual
  release binary still need to be captured from a real release build; see
  [../BRAND_TRADEMARK_REVIEW.md](../BRAND_TRADEMARK_REVIEW.md) and
  [../../CONTROLLED_ALPHA_PACKAGE_CHECKLIST.md](../../CONTROLLED_ALPHA_PACKAGE_CHECKLIST.md).
* The Tari Ootle event template compiled WASM shipped as a release asset
  needs its own provenance line in `THIRD_PARTY_NOTICES.md`; the template
  source in `templates/ootle-anchor-event-template-v2/` is project-owned
  under `MIT OR Apache-2.0`, but the compiled binary carries reproducibility
  metadata that a release should record.
