# Linux native dependency license notes

Companion to the Rust and npm transitive reports and to the Windows
release-configuration companion document
[WINDOWS_NATIVE_DEPENDENCIES.md](WINDOWS_NATIVE_DEPENDENCIES.md). Applies
to the current Linux release configuration (Rust
`1.97.1-x86_64-unknown-linux-gnu`, Tauri 2 `.deb` / `.rpm` / `.AppImage`
bundle on Ubuntu 24.04 LTS, GLIBC 2.39).

The Linux release does **not** statically link OpenSSL. Rust's `aws-lc-rs`
(via `aws-lc-sys`) provides the cryptographic primitives used by `rustls`,
and it is built from source and statically linked into the release binary
during `cargo build --release` (no system library is linked). The
Rust-side wrappers `openssl-sys` / `openssl-probe` remain in the workspace
dependency graph (they are pulled in by unrelated transitives), but the
Linux Tauri build does not link them against a system OpenSSL, so the
distributed Linux executable does **not** carry a redistribution
requirement for OpenSSL.

## Toolchain and system dependencies used to build the Linux release

The Linux Tauri release build requires the following Ubuntu 24.04 (or
newer) packages at BUILD time; none of them is bundled into the shipped
`.deb`, `.rpm`, or `.AppImage` beyond what Tauri's linuxdeploy step
copies into the AppImage's `usr/lib/` tree:

```
libwebkit2gtk-4.1-dev
build-essential
curl
wget
file
libxdo-dev
libssl-dev
libayatana-appindicator3-dev
librsvg2-dev
libdbus-1-dev
patchelf
```

The Tauri bundler also relies on `dpkg-deb` (Debian), `rpmbuild` (rpm)
and `linuxdeploy` (AppImage — downloaded automatically by Tauri on first
run). `linuxdeploy` is redistributed by upstream under GPL-3.0; it is
not bundled into the shipped artifacts. See
`docs/release/BRAND_TRADEMARK_REVIEW.md` for shipping copy.

## OS credential storage

The desktop Linux release uses the Secret Service D-Bus API for the
`walletd` API-key credential store (`gui/src-tauri/Cargo.toml`, feature
`sync-secret-service`; see `gui/src-tauri/src/walletd_credential_store.rs`).
On a normal Linux desktop this is provided by `gnome-keyring-daemon`
(default in GNOME) or `kwalletmanager5` (KDE). Headless / server hosts
without either daemon report `WalletdCredentialStoreError::Unavailable`
and the shell falls back to the documented `WALLETD_AUTH_TOKEN`
environment variable path.

## Runtime dependencies of the `.deb`

`Depends: libwebkit2gtk-4.1-0, libgtk-3-0`

All other transitive shared libraries are already declared as required
by `libwebkit2gtk-4.1-0` (`libgtk-3-0`, `libglib2.0-0t64`,
`libcairo2`, `libdbus-1-3`, etc.). No additional apt package needs to
be listed in the `.deb` control file.

## AppImage bundling

Tauri's AppImage step invokes `linuxdeploy`, which copies the
transitive shared-library closure of the app binary into the AppDir's
`usr/lib/` tree (223 files, 84 MB compressed AppImage). The AppImage
carries GTK 3, GDK-Pixbuf, Cairo, Pango, X11 client libs, Wayland
libs, freetype, fontconfig, libpng, libjpeg, and the GTK input-method
modules (`im-*.so`). Its ELF is `static-pie linked` per `file(1)`.

Every bundled shared library is a system-supplied Ubuntu package and
its license notice belongs in a NOTICES file distributed next to the
AppImage. The full set is captured by the AppImage build log and can
be regenerated with `ldd $(unsquashfs -l ...) usr/bin/tari-cc-private-ballot-gui`.

## Managed-Tor executable

The Linux release does not bundle Tor. Operators install their own
`tor` binary (typically `/usr/bin/tor` from Ubuntu's `tor` package or
the Tor Project's Debian repository) and select it in the app. The
executable-picker validator now enforces the Unix executable bit in
addition to the existing checks (absolute path, real regular file,
no control characters, no symlink) —
see `gui/src-tauri/src/tor_support.rs`.
